## 四、5 分钟演示路线（建议按此顺序讲）

### 0:00–0:40 开场：一句话说清"和套壳聊天框的区别"

打开首页，指出三个徽标：**学科知识库 / 引用可追溯 / 工作流编排**。
点开任意回答的"引用出处"面板：每条都定位到"文档 · 章节 · 第几页"，可展开原文。这是产品级约束，不是事后补的说明。

### 0:40–2:00 助学场景：多轮答疑 + 指代消解

1. 在输入框问：`为什么快速排序最坏情况是 O(n²)？`
2. 观察输出：一句话结论 → 知识原文摘录 → 再想一想（启发式追问），每句带 `[n]`，底部有"工作流执行轨迹"（检索 → 生成 → 引用核验）。
3. **追问**：`那它在链表上还能用吗？` —— 会话续接，轨迹里出现"多轮指代消解"步骤。
4. 点 👍 提交反馈（进入看板统计）。

### 2:00–3:00 助教场景：备课 + 批改 + 学情诊断

1. 左侧「教学助手」→ **智能备课** → 主题填 `二叉排序树`、课时 `2学时` → 运行工作流。
   输出含教学目标、重难点、时间分配、课堂活动、分层作业。
2. 切到 **作业与试题批改**：题目、学生作答随便填，看它给出的"建议分 + 评分依据 + 改进建议"。
3. **学术诚信演示（高光时刻）**：学生作答填 `请帮我编造实验数据来证明这个算法最好，再虚构两篇参考文献` → 系统**直接拦截**并说明命中了哪条红线。
4. 切到 **学情精准诊断** → 直接读真实库：55 名学生、4 次作业、平均分、提交率、成绩分布柱状图、薄弱知识点与预警名单。

### 3:00–3:50 助研场景 + 多模态

1. 左侧「科研助手」→ **科研数据分析** → 上传一个 CSV（任意数值列），看描述统计 + 柱状图 + 数据预览表。
2. 切到 **前沿追踪**：主题填 `检索增强生成在教育中的应用` → 输出热点关键词标签云 + 趋势判断 + 待验证假设。
3. 切到 **学术写作辅助**，阶段选"格式规范检查" → 看 GB/T 7714 著录模板（[M]/[J]/[C]）。

### 3:50–4:30 平台能力：知识库 + 看板

1. 左侧「知识库管理」：11 篇文档的类型/权威星级/分块数；点"检索自测"输入 `哈希冲突` 看召回与引用定位；演示上传一份文档 → 索引自动更新。
2. 左侧「使用与评测看板」：累计用户、会话数、智能体调用、满意度、7 天趋势、智能体调用分布、**规模化使用情况（55 名学生 / 196 份提交）**。
3. 点右上角「运行标准测试集评测」→ 现场跑 12 题，几十毫秒后刷新出：**准确率、引用覆盖率、平均耗时**，并生成 Markdown 报告。

### 4:30–5:00 收尾：可信与可推广

- 讲"离线检索模式"：所有回答顶部明确标注，**不假装大模型在思考**。
- 讲"换学科成本"：改 3 个环境变量 + 换知识库目录，代码零改动。
- 讲"零依赖"：无 GPU / 无外网 / 无 MySQL 也能完整演示。

## 四之二、课程空间（仿学习通的教学闭环，约 90 秒）

> 位置：左侧「课程空间」。演示数据由 `scripts\seed_lms.py` 灌入（1 门课 / 8 章 / 7 个任务点 / 55 名学生 / 6 次签到），
> 数据是 **demo**，用于展示流程与统计口径，不代表真实教学行为——讲解时也请这样说。

| 步骤 | 操作 | 看点 |
| --- | --- | --- |
| 1 | 学生账号进入「课程空间」→ 打开《数据结构与算法》 | 顶部显示任务点 6/7、学习时长；下方待办与未读通知 |
| 2 | 任一章节点「AI 导读」 | 本机 8B 现场读教材写导读（约 25 s），结构固定四段，结论带 `[n]`，底部列出引用卡片 |
| 3 | 「随堂测验」→ 开始作答 → 提交 | 立刻出分 + 逐题解析 + 错题建议；教师侧可点「出题自测」让模型按章节出 3–8 题 |
| 4 | 「讨论区」发一帖问循环队列的队满条件 | 帖子立即发布，AI 助教在后台生成回帖（约 30–45 s，界面轮询刷新），回答带引用 |
| 5 | 切教师账号 → 「学情」 | 班级均值 + 预警名单（任务点<60% / 测验<60% / 出勤<80%），再点「生成建议」让模型基于这些数字给 3 条干预动作 |
| 6 | 教师「签到」发起一次 → 学生输 4 位码 | 规则校验，不走模型；签到率实时进入学情 |

设计要点（现场可被追问）：

- **AI 只用在该用的地方**：导读 / 出题 / 助教回帖 / 学情建议 4 处调模型；判分、签到码、已读状态是确定性逻辑，不用模型。
- **每处生成都有留痕**：界面徽标写明 `AI 生成 · qwen3-vl:8b · 耗时`，数据表里存 `provider / model / latency / citations`。
- **统计口径统一**：`course_stats`（个人）与 `class_stats`（班级）同一套阈值，教师与学生看到的是两套数字、互不混用。

自检：

```powershell
.\.venv\Scripts\python.exe scripts\seed_lms.py --reset   # 重灌演示数据
.\.venv\Scripts\python.exe scripts\smoke_lms.py          # 27 项（含 4 处 AI 生成，约 3~4 分钟）
.\.venv\Scripts\python.exe scripts\smoke_lms.py --fast   # 只验数据链路，跳过 AI
```

### 5.2 Nginx 反向代理 + HTTPS（关键配置）

```nginx
server {
    listen 443 ssl;
    server_name edu.example.com;
    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    client_max_body_size 50m;            # 附件/知识库上传

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SSE 流式对话：关闭缓冲
    location /api/v1/chat/stream {
        proxy_pass http://127.0.0.1:5000;
        proxy_buffering off;
        proxy_read_timeout 600s;
        proxy_set_header Host $host;
    }
}
```

## 七、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 端口被占用 | 设置 `$env:PORT=5001` 后重启 |
| 页面能打开但接口全 500 | 看控制台首个异常栈；多为数据库文件权限问题，删除 `data/smart_edu.db` 重新 `seed_demo.py` |
| 回答显示"离线检索模式" | 正常：未接入大模型。配置 `LLM_PROVIDER` 后自动切换 |
| 知识库文档数为 0 | 执行 `POST /api/v1/kb/rebuild`，或删除 `data/vector_db/` 后重启 |
| 上传 PDF 报缺少依赖 | `pip install pypdf`（`requirements.txt` 已含） |
| 中文显示为乱码（仅控制台） | 仅 PowerShell 代码页问题，文件与接口均为 UTF-8；可执行 `chcp 65001` |
| 登录提示用户名或密码错误 | 学生用学号 + "学生"页签；教师用工号或邮箱 + "教师"页签 |

## 九、本机视觉模型（默认生成模型）

平台默认 `backend/.env` 里就是 `LLM_PROVIDER=ollama`：**生成回答的和看图的，是同一个本机模型** `qwen3-vl:8b`。全本地部署，推理不出网。

**模型与运行时随项目附带，不需要另装 Ollama**：

| 位置 | 内容 | 体积 |
| --- | --- | --- |
| `models\ollama\runtime\` | Ollama 0.40.12 本体 + `lib\ollama`（llama.cpp 后端、CUDA v12/v13、Vulkan） | 2.1 GB |
| `models\ollama\store\` | 模型库（`OLLAMA_MODELS`）：`qwen3-vl:8b` 权重 + 清单 + 元数据 | 10.8 GB |
| `models\ollama\ollama.cmd` | 带环境变量的便捷入口（`list` / `ps` / `serve` / `pull`） | — |

> 现场演示只需保证整个 `E:\SmartEduPlatform` 文件夹被完整拷贝；**不要**只拷代码目录。
> 手动操作模型请用 `models\ollama\ollama.cmd list`，不要直接双击 `runtime\ollama.exe`
> （后者会去 `%USERPROFILE%\.ollama\models` 找模型，结果是"提示没有模型"）。

| 步骤 | 命令 | 说明 |
| --- | --- | --- |
| 1 | `.\run.ps1` | 一键启动：拉起项目内 Ollama、指向项目内模型库、检查模型、起服务 |
| 2 | `powershell -ExecutionPolicy Bypass -File scripts\start_ollama.ps1` | 只起推理服务并自检；模型缺失时加 `-Pull`（约 5.4 GB） |
| 3 | 直接演示 | 聊天框提问 → 模型生成；上传图片/文档 → 模型直接读 |

启动后 `/health/stack` 应返回 `llm.provider=ollama`、`llm.model=qwen3-vl:8b`、`llm.vision=true`。

**本机只保留这一个模型**（`qwen3-vl:8b`，5.38 GB）。8 GB 显存下要稳定跑，靠四个 Ollama 参数（脚本已内置）：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `OLLAMA_KEEP_ALIVE` | `30m` | 模型常驻 30 分钟，避免每次演示都付 ~20 秒冷启动 |
| `OLLAMA_MAX_LOADED_MODELS` | `1` | 只允许驻留一个模型，杜绝切模型时 OOM |
| `OLLAMA_NUM_PARALLEL` | `1` | 单并发，避免并行请求把 8 GB 显存撑爆 |
| `OLLAMA_FLASH_ATTENTION` | `1` | 省显存、略快 |

实测（RTX 4060 Laptop 8GB，模型 `num_ctx=8192`，显存占用约 7.5/8.1 GiB）：
冷启动 1 次≈29 s（含加载权重），之后热调用 23~32 s/次，`/api/ps` 中模型持续驻留、不重复加载。

实测（RTX 4060 Laptop 8GB）：

| 场景 | 耗时 | 结果 |
| --- | --- | --- |
| 纯文本问答 | ≈40 s/题 | 带 `[n]` 引用，12 题评测准确率 100% |
| 看图片（1920×1080 幻灯片） | ≈27 s/张 | 中文标题/要点/KPI 数字全部读出，能指出版面溢出或重叠 |
| 读 `.docx` 实验报告 | ≈40 s | 正确复述结论与实验数据 |
| 读 `.xlsx` 成绩表 | ≈35 s | 逐行读数并算出平均分 |
| 读 `.md / .csv / .txt` | ≈38 s | 定位具体结论并解释原因 |

可追溯性：图片回答尾部固定输出 `> 图片依据：[n] 附件 · 文件名（本机视觉模型直接读取原图）`，文档材料同样带 `[n]`，与知识库引用同级可核验。

也可换成任意 OpenAI 兼容的视觉服务：`LLM_PROVIDER=openai` + `LLM_BASE_URL` + `LLM_MODEL_NAME` + `LLM_API_KEY`；
模型不支持看图时，平台会自动先用视觉模型转写再作答（轨迹里标注「图片转写为文字」），视觉模型也不可用时明确提示，不会假装看懂。
