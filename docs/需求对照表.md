## 三、核心功能要求（（二）核心功能要求，第 1—4 项为必须，第 5—8 项为加分）

### （1）深度贴合场景需求 —— 已实现

- **业务痛点真实**：备课耗时、主观题批改口径不一、学情统计靠手工、学生找不到针对性资源、科研文献综述耗时长。
- **生成内容符合学科规范**：复杂度一律标注 `O(...)`（含 `O(n²)` 上标不丢失）；参考文献按 **GB/T 7714—2015** 著录（[M]/[J]/[C]/[D]/[S]/[EB/OL]）；代码规范按 PEP 8 / Google C++ Style。
- **验证**：`scripts/smoke_test.py` 第 5 节验证备课输出含"教学目标"、批改输出含建议分、诊断输出含真实指标。

### （2）交互自然流畅 —— 已实现

- 自然语言发起任务：所有智能体均可直接用中文描述需求，无需记忆指令。
- **上下文理解与歧义消解**：`agents._resolve_query` + 会话历史拼接，追问"那它呢""这个算法"会继承上文主题；工作流轨迹里会记录"多轮指代消解"这一步及其判断结果。
- **多轮连贯对话**：`Conversation` / `Message` 持久化，`conversation_id` 续接；历史会话可在侧栏点开继续。
- **清晰友好的反馈**：加载骨架屏 → 结果卡片（结论 / 引用 / 轨迹 / 图表）→ 后续问题推荐 → 复制/导出 Markdown。
- **验证**：`smoke_test.py` 第 4 节连续两轮提问，校验返回同一 `conversation_id`。

### （3）知识权威可信 —— 已实现

- 知识源分层：教材（authority 4-5）、课程大纲与标准（5）、教学案例（3）、学术论文（3-4）。
- 每个知识块携带 `locator`（文档 · 章节 · 页码）、`source_type_label`、`authority`，检索时按权威度加权（`authority_weight`）。
- 检索质量护栏：剥离疑问词后再打分；同时用词覆盖率与连续短语命中压制"只碰一个罕见词"的噪声段落。
- 生成侧约束：只允许依据检索材料作答，材料不足时明确说明"知识库暂未检索到"，不编造。
- **验证**：知识库页面可查看每份文档的类型、权威星级、知识块数；点开引用卡片可看到原文片段。

### （4）内容可追溯 —— 已实现

- 回答正文逐句标 `[n]`，文末/卡片给出 `locator` + 原文片段 + 相关度 + 权威度。
- 工作流轨迹（`trace`）记录每一步：检索命中数、生成本后端与耗时、引用核验结果（"引用命中 4/5 条，未引用编号 [4]"）。
- 引用核验步骤会剔除回答中未被使用的引用编号，避免"挂着一堆没用的参考文献"。
- **验证**：`smoke_test.py` 校验每条检索结果都有 `locator`；`/chat` 返回 `citations` 与 `trace`。

### （5）成果的可复制与可推广性 —— 已实现

- **配置化换学科**：`DISCIPLINE_NAME`、`DISCIPLINE_COURSE`、`KB_DOC_DIR` 改环境变量即可；代码零改动。
- **零依赖降级**：MySQL 缺失→SQLite；GPU/大模型缺失→离线检索模式；`numpy` 缺失→纯 BM25。任何环境都能演示。
- **规模化数据**：内置 55 名学生 / 4 次作业 / 196 份提交，看板实时展示覆盖人数、提交量、满意度。
- **一键部署**：`pip install -r requirements.txt` + `python backend/app.py`，前端由 Flask 同源托管。
- **验证**：`/api/v1/analytics/overview` 的 `scale.reaches_50_users` 为 `true`。

### （6）生成内容多元性（规范性 + 可自定义） —— 已实现

- **规范性**：著录格式、复杂度标注、代码规范、学术诚信检查均有硬约束与检查步骤。
- **可自定义**：学习者画像（水平/目标/表达风格/讲解深度/薄弱点）影响讲解策略；智能体输入支持课时长度、授课对象、题目满分、分析类型、时间窗口、周数/每周时长等参数；同一问题不同画像会得到不同深度与风格的输出。
- **验证**：同一问题在 `beginner` 与 `advanced` 画像下，`detail_level` 与段落数不同（可在「学习画像」页切换后对比）。

### （7）复杂问题求解 —— 已实现

- 专用智能体 `complex_solver`：**问题界定 → 任务拆解 → 分层求解 → 可能踩坑 → 可执行第一步**。
- 设计上刻意"给方法而不是给答案"：拆解为可检验子任务、给出验证方式与思维拓展，激发自主思考。
- **验证**：`smoke_test.py` 第 6 节输入"设计千万级实时排行榜"，校验输出含拆解结构。

### （8）个性化与自适应 —— 已实现

- `UserProfile`：`level`（入门/进阶/提高）、`goal`、`learning_style`（均衡/简洁/启发/案例）、`detail_level`、`weak_points`。
- 画像实时作用于：答疑讲解深度、学习路径阶段划分、练习推荐、错题归因的追问角度。
- 薄弱点自动归纳：`POST /profile/weak-points`，从错题与提问中累计。
- **验证**：「学习画像」页面可读写；`/api/v1/profile` 返回 `interactions` 计数。

## 三之二、教学闭环补充对照（仿学习通 · 本地大模型驱动）

赛题原文对"场景"的界定是**真实教学或科研场景的实际需求**。答疑、备课、批改是"点状"能力，
真实课堂还需要有组织形态的载体。因此平台补了一层「课程空间」，形态参照超星学习通，
但 AI 全部跑在本机模型上，每处生成都可核对——这一层把第 1（贴合场景）、第 5（规模化可推广）、
第 8（个性化与自适应）三项从"演示"推到"可用"。

| 学习通对应功能 | 平台实现 | AI 参与方式与留痕 | 代码位置 |
| --- | --- | --- | --- |
| 课程 / 班级 | 建课、邀请码 `DS2026` 加入、课程成员表 | 不参与 | `backend/lms_models.py`、`lms_routes.list_courses/create_course/join_course` |
| 章节任务点与进度 | 8 章 / 7 个任务点，`todo→doing→done` + 学习时长累计 | **AI 课前导读**：结构固定四段，结论逐条 `[n]` 引用教材；结果缓存，记录 `provider/model/latency/citations` | `lms_routes.chapter_intro`、`update_progress` |
| 随堂测验 | 按章节生成 3–8 道单选，提交即判分、逐题解析、错题建议 | **AI 命题 + 解析**：只依据检索到的教材片段出题，答案下标合法性校验通过才入库 | `lms_routes.generate_quiz`、`submit_quiz` |
| 讨论区 | 发帖 / 回复 / 置顶 | **AI 助教自动回帖**：学生发帖后后台线程生成 ≤200 字回答，带 `[n]` 引用；前端轮询刷新，不阻塞发帖 | `lms_routes.create_discussion`、`_ai_tutor_reply` |
| 签到 | 教师发起 4 位签到码（10 分钟有效），学生签到、签到率实时统计 | 不参与（确定性规则，不为了"显得智能"而调用模型） | `lms_routes.create_signin`、`checkin` |
| 通知 | 发布 / 置顶 / 未读红点 / 标记已读 | 不参与（同上） | `lms_routes.create_notice`、`read_notice` |
| 学情统计 | 个人口径（完成率/测验均分/出勤/时长）与班级口径（均值 + 预警名单）分开计算 | **AI 学情建议**：把真实统计喂给本机模型，输出"一句话结论 + 3 条当天可执行动作"，显式要求"只依据给定数字" | `lms_routes.course_stats/class_stats/learning_advice` |

**验证方式**（可复现）：

```powershell
.\.venv\Scripts\python.exe scripts\seed_lms.py --reset   # 灌演示数据（1 门课 / 55 名学生 / 6 次签到）
.\.venv\Scripts\python.exe scripts\smoke_lms.py          # 27 项：数据链路 + 4 处 AI 生成
```

**诚实的边界**：课程空间的 55 名学生、作答记录、签到记录均为**演示数据**（脚本生成、结果确定），
用于展示统计口径与流程，不代表真实教学行为；真实使用需由教务导入名单后自然积累。
