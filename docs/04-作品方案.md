# 作品方案：灵眸智教

**赛题**：XH-202620 面向一流学科建设的学科垂类大模型与创新应用开发
**学科**：计算机科学与技术（课程载体：数据结构与算法）
**一句话定位**：把"会聊天的大模型"改造成"讲得对、查得到、能复核"的学科助教。

> 本文件是《04—作品方案》PPT 的完整文字底稿，配套演示文件：`docs/灵眸智教-作品方案.pptx`。

## 一、作品阐述

### 1.1 我们看到的真问题

在《数据结构与算法》这类"概念细、易混淆、重推理"的课程里，师生共同面对三个痛点：

1. **学生问不清、AI 答不准**：通用大模型会自信地把"快速排序最坏时间复杂度"答成 O(n log n)，把"空间复杂度"讲成"时间复杂度"，学生无法判断对错，还学会了错误结论。
2. **教师被重复劳动淹没**：一次 2 学时备课 60–90 分钟；主观题批改平均 3 分钟一份且标准不一；全班学情统计靠手工汇总。
3. **科研入门缺方法**：文献综述耗时、数据看不透、格式反复返工，而通用模型给不了"可核查"的文献与规范。

### 1.2 我们的解法

以**学科知识库为事实底座**，用**可编排工作流**把"检索—推理—核验—呈现"固化成流程，并给每个结论挂上**可点开的出处**：

- 回答里每个 `[n]` 都能定位到"哪本教材、哪一节、第几页"，点开即见原文；
- 检索层内置**学科消歧**：问"时间复杂度"不会拿"空间复杂度"作答，问"二叉排序树"不会拿"哈希表"作答；
- 没有 GPU、没有外网也能跑：自动切换**离线检索模式**，并明确标注，不假装大模型在思考。

### 1.3 价值主张

| 对谁 | 价值 |
| --- | --- |
| 学生 | 得到"对且查得到"的答案 + 启发式追问，而不是一段无法验证的流畅文本 |
| 教师 | 备课/批改/学情诊断从"小时级"降到"分钟级"，且评分依据可解释 |
| 研究者 | 文献脉络、数据统计、GB/T 7714 著录规范一站式 |
| 学校 | 换学科只改 3 个配置项，一套平台可复制到多学科 |

## 二、功能思路

### 2.1 三场景闭环（12 个智能体）

```text
助学 ── 智能答疑 · 学习路径规划 · 错题归因 · 自测练习 · 复杂问题求解
助教 ── 智能备课 · 作业批改 · 学情诊断 · 课件素材生成
助研 ── 前沿追踪 · 学术写作辅助 · 科研数据分析
```

每个智能体不是"一个提示词"，而是**一条带条件分支的工作流**。以"学情诊断"为例：

```text
汇聚数据 → 计算班级指标 → 按知识点聚合成绩 → 识别薄弱点（阈值+排序）
        → 检索对应章节易错点 → 生成干预建议 → 输出图表与预警名单
```

以"作业批改"为例，第一步就是**学术诚信检查**：命中"编造数据/虚构文献/代写论文"直接拦截并说明红线，而不是先写一段漂亮的评语。

### 2.2 交互设计

1. **自然语言发起**：不需要记指令，直接说"帮我准备两课时的二叉排序树"。
2. **多轮连贯**：会话持久化 + 指代消解，"那它呢"能接上文；轨迹里会显示"多轮指代消解"这一步。
3. **结果结构化呈现**：一句话结论 → 知识原文摘录 → 再想一想；表格、柱状图、时间线、关键词标签按内容类型自动选择。
4. **反馈闭环**：每条回答可 👍/👎 + 评论，进入看板统计。
5. **导出可用**：一键复制/导出 Markdown，直接贴进教案或作业反馈。

### 2.3 个性化（第 8 项要求）

学习画像记录 `水平 / 目标 / 表达风格 / 讲解深度 / 薄弱点`，直接影响：

- 答疑的讲解深度（入门 → 先讲类比，提高 → 直接给复杂度分析）；
- 学习路径的阶段划分与资源清单；
- 练习推荐难度；
- 错题归因的追问角度。

薄弱点从错题与提问中自动累计，可在「学习画像」页查看与编辑。

### 2.4 课程空间：把"答疑"接进真实教学流程（仿学习通）

只做聊天框，学生用完就走；真实课堂是**有组织形态**的：课程、章节任务点、随堂测验、讨论、签到、通知。
所以我们在同一套界面里补了一层"课程空间"，形态参照学习通，但**每一处 AI 都跑在本机模型上、且必须可核对**：

| 模块 | 学生侧 | 教师侧 | 本地大模型在这里做什么 |
| --- | --- | --- | --- |
| 课程 / 章节任务点 | 看任务点、标记完成、累计学习时长 | 建课、发邀请码、看全班进度 | 为每个任务点生成**课前导读**（结构固定：解决什么问题 / 三个必会要点 / 常见误区 / 自测一问），结论逐条标 `[n]` 教材引用 |
| 随堂测验 | 作答、立刻出分、看逐题解析 | 按章节一键出题（3–8 题） | 命题、写解析；题目必须落在教材原文范围内，出题结果落库并记录 `provider / model / latency` |
| 讨论区 | 发帖提问、追问 | 回帖、置顶 | 学生发帖后自动以「AI 助教」回帖，答案 ≤200 字并带 `[n]` 引用；学生可再追问教师 |
| 签到 | 输 4 位码签到 | 发起签到（10 分钟有效）、看签到率 | 不参与（纯规则，避免把简单事情包装成 AI） |
| 通知 | 未读红点、标记已读 | 发布 / 置顶通知 | 不参与（同上） |
| 学情 | 个人完成率 / 测验均分 / 出勤 / 时长 | 班级均值 + **预警名单**（任务点<60% 或 测验<60% 或 出勤<80%） | **AI 学情建议**：把上面这些真实数字交给本机模型，输出"一句话结论 + 3 条当天可执行动作"，并明确要求"只依据给定数字，不要虚构" |

设计上守三条线：

1. **数据真实**：所有统计都从库里按 SQL 现算（`course_stats` / `class_stats`），不预生成、不美化；演示数据在脚本与文档里明确标注 demo。
2. **AI 可核对**：导读、出题、助教回帖、学情建议四处生成，界面都挂 `AI 生成 · 模型名 · 耗时` 徽标，回帖与导读还列出引用卡片。
3. **不硬蹭 AI**：签到码校验、通知已读、测验判分这类确定性逻辑不用模型，避免"为了显得智能而变慢"。

> 截图（真实运行，数据为演示数据）：`docs/img/lms-chapters.png`、`lms-quiz.png`、`lms-discuss.png`、`lms-dashboard.png`。

## 三、技术方案

### 3.1 总体架构

```text
前端 SPA（原生 JS + Tailwind，Flask 同源托管）
   ↓ REST /api/v1（Bearer Token）
Flask 应用层：鉴权 · 资源 · 聊天（含 SSE 流式）
   ↓
智能体工作流引擎：声明式注册 → 检索 → 工具 → 分支 → 引用核验 → 轨迹
   ↓
知识库（分块/元数据/混合检索）+ LLM 客户端（本地/星火/OpenAI/离线）
   ↓
数据层：MySQL 或 SQLite（自动降级）
```

### 3.2 知识库构建

- 11 份文档 / 81 个知识块：教材 7 章 + 课程大纲 + 代码与学术诚信规范 + 教学案例 + 学术论文；
- 每块带元数据：`source_type`（教材/标准/大纲/案例/论文）、`authority`（1–5）、作者、年份、出版社、标签；
- Markdown 标题分块 + 页码范围标注，生成 `locator`（文档 · 章节 · 页码）；
- 支持页面增量上传、删除、一键重建索引。

### 3.3 检索：多信号融合 + 学科消歧

```text
查询清洗（剥离疑问词）
  → BM25（中文二元组，精确术语）
  → 哈希向量（512 维，语义近似）
  → 查询词覆盖率（idf 加权）
  → 连续短语命中
  → 标题/章节命中
  → 权威度加权
  → 成对概念消歧（时间↔空间、最好↔最坏、稳定↔不稳定…12 组）
  → 实体一致性（快速排序 vs 希尔排序…30+ 实体）
```

检索名次还会作为生成阶段的先验，保证摘录段落"对题"。

**检索内核（工程实现）**：每个知识块的分词与集合特征在索引加载时算一次，逐块打分交给
C++ 内核（`native/kbcore.cpp`，纯 C++17、零第三方依赖、C ABI 动态库经 ctypes 调用）。
分工上，C++ 只做 `O(N×Q)` 的打分循环（BM25 / 标题命中 / 正文覆盖率 / 成对概念惩罚 / 实体奖惩），
分词、向量余弦（numpy/BLAS）与引用格式化仍在 Python，因此两边分词结果完全一致。

| 知识块数 | 原实现 | 现实现（C++） |
| --- | --- | --- |
| 81（演示库） | 24.1 ms | 0.1 ms |
| 4,860 | 1.37 s | 0.7 ms |
| 48,600（学科级） | 14.03 s | 6.1 ms |

等价性由 `scripts/verify_kb_equiv.py` 保证：30 条查询 top-10 的 `chunk_id / score / coverage`
与原实现逐位相同。内核未编译时自动回退纯 Python 引擎（功能不变，学科级规模下慢约 30 倍），
`/api/v1/health/stack` 的 `knowledge_base.engine` 如实标注当前引擎。

> 为什么不全站换语言：一次问答 23–40 秒里，模型推理占 99.9%，Python 业务层只有 20–50 毫秒；
> 把力气花在检索算法与内核上，收益比整体重写大两个数量级。

### 3.4 生成：四种后端 + 诚实降级

**默认用的是 `ollama` 后端，模型是 `qwen3-vl:8b`（多模态，能直接看图）**，跑在本机 Ollama 上，推理不出网。

| 后端 | 条件 | 行为 | 能否识图 |
| --- | --- | --- | --- |
| `ollama`（**当前默认，也是唯一在用**） | 本机 Ollama + `qwen3-vl:8b` | 本机视觉大模型，文本与图片统一入口 | ✅ 能 |
| `local`（可选，仓库不含权重） | torch + `LLM_MODEL_PATH` 指向自行下载的权重 | 直连 HuggingFace 权重，纯文本推理 | ❌ 不能 |
| `spark` | 配置星火 Key | 讯飞星火 OpenAI 兼容接口 | 按服务能力 |
| `openai` | 配置网关 | 任意 OpenAI 兼容服务 | 按服务能力 |
| `offline` | 以上都不可用 | 知识库原文结构化编排 + 显式"离线检索模式"标识 | ❌ |

> 说明：仓库内已**不再内置任何权重**。原先 `models/llm/qwen--Qwen2.5-7B-Instruct/`（14.2 GB，纯文本、不能识图）
> 只被 `training/train_lora.py` 当默认基座，运行时从未加载；为避免"用的到底是不是能识图的模型"这类误解，该权重已删除，
> 微调脚本改为 `--base` 必填（推荐 `Qwen/Qwen3-VL-8B-Instruct`，与线上模型同源）。
> 判断"当前到底用哪个"不要看文档，要看 `GET /api/v1/health/stack` 的 `llm` 字段（`provider/model/vision`）——界面右上的徽标和设置面板都是实时读这个接口。

关键约束：**只依据检索材料作答**；引用编号必须来自检索结果，未使用的引用会被剔除；资料不足时明确说"知识库未覆盖"。

### 3.5 模型微调（LoRA / SFT）

- `training/build_dataset.py`：由知识库章节 + 人工种子问答对生成 Alpaca 指令集（含出处标注）；
- `training/train_lora.py`：Qwen chat template、只对 assistant 段计 loss、QLoRA（r=16/α=32，7 个投影层）、支持合并导出；
- 基座权重**不进仓库**，`--base` 必填（推荐 `Qwen/Qwen3-VL-8B-Instruct`，与运行中的模型同源；纯文本实验也可用 `Qwen2.5-7B-Instruct`）；
- 实测：种子 14 条 + 知识库自动生成 78 条 = 79 条样本可跑通完整训练链路（真实训练需千级样本）。

### 3.6 多模态

- **生成模型本身就是视觉模型**：`LLM_PROVIDER=ollama` → 本机 `qwen3-vl:8b`，对话与看图用同一个模型，不需要额外中转，推理全程不出网；
- 图片路径：附件图片压缩到长边 1600px → 以 `image_url` **直接进模型**（工作流轨迹里显示「图片直读」），模型看到的是原图而不是 OCR 残文；
- 文档路径：`.pdf / .docx / .xlsx / .md / .csv / .txt` 解析成正文 → 作为「附件 · 文件名」材料并入本轮上下文，并回查知识库做知识点对齐；
- 可核验：图片回答尾部固定输出 `> 图片依据：[n] 附件 · 文件名（本机视觉模型直接读取原图）`，文档材料同样带 `[n]` 引用；
- 诚实降级：模型不支持看图时，先用视觉模型转写再作答（轨迹标注「图片转写为文字」）；视觉模型不可用时明确提示，绝不假装看懂；
- 上下文保护：本机模型上下文 8192，附件正文按 `LLM_CONTEXT_CHARS`（默认 6000 字）截断，检索资料同步收窄，宁可少读也不撑爆；
- 输出：Markdown、表格、柱状图、KPI 卡片、时间线、关键词标签、数据预览表。

### 3.7 工程与部署

- 零重型依赖启动：不装 torch 也能完整演示；
- 自动降级：MySQL → SQLite；向量后端 → 纯 BM25；
- 一键部署：`pip install -r requirements.txt` + `python backend/app.py`；
- 生产：gunicorn + Nginx（含 SSE 不缓冲配置）。

## 六、创新之处

1. **把"可追溯"做成产品级约束**，不是文档里的承诺：引用编号必须来自检索、未使用即剔除、每条可点开原文，且检索名次会反过来约束生成段落的选材。
2. **学科消歧进入检索层**：成对概念表（时间/空间、最好/最坏、稳定/不稳定）+ 学科实体表（30+ 算法与结构），这是通用向量检索给不了的精度。
3. **工作流而非提示词**：12 个智能体各有步骤、分支、失败降级与轨迹，评审能看到"它怎么想的"。
4. **诚实降级**：没有大模型时不伪装，切离线编排并显式标注——这恰恰是可信 AI 的底线。
5. **零依赖可复现**：无 GPU / 无外网 / 无 MySQL 也能完整演示，评审核验成本极低。
6. **学术诚信守卫**：不是关键词黑名单，而是带否定语境识别的守卫（"如何避免编造数据"不会被误伤）。
