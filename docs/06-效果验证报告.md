### 2.6 检索性能（三种实现对照，同一台机器同一批查询）

「检索」是整条链路里唯一能靠工程手段压下来的部分：一次问答 23–40 秒中，模型推理占 99.9%。
因此把检索的逐块打分做成 C++ 内核，并把每个知识块的分词结果预先算好。

| 知识块数 | 原实现 p50 | Python 预计算索引 | C++ 内核 | C++ 相对原实现 |
| --- | --- | --- | --- | --- |
| 81（当前演示库） | 24.1 ms | 0.3 ms | **0.1 ms** | 241× |
| 810 | 227.8 ms | 2.2 ms | **0.2 ms** | 1139× |
| 4,860 | 1,372.7 ms | 16.6 ms | **0.7 ms** | 1961× |
| 16,200 | 4,722.8 ms | 51.7 ms | **1.9 ms** | 2486× |
| 48,600（学科级规模） | 14,032.6 ms | 152.7 ms | **6.1 ms** | 2300× |

| 口径 | 说明 |
| --- | --- |
| 方法 | 5 条查询 × 3 轮取 p50；`scripts/bench_kb.py --engine python / cpp` |
| 瓶颈定位 | 改动前每次 `search()` 把每个块正文重新分词 4~5 次（BM25 一次、标题一次、覆盖率两次、短语一次），占 85% 耗时 |
| 等价性 | `scripts/verify_kb_equiv.py`：30 条查询的 top-10 在 `chunk_id / score / coverage` 三个维度与原实现**逐位相同** |
| 端到端影响 | 81 块时检索从 24 ms 降到 0.1 ms，但整题仍是 23–40 s —— **延迟不由语言决定**；上 C++ 是为了学科级知识库（万块以上）不塌 |
| 中立性 | 内核可选：未编译/加载失败时自动回退纯 Python 引擎，`/health/stack` 的 `knowledge_base.engine` 如实显示 `cpp` 或 `python` |

### 案例一：概念辨析 + 因果推理（助学 · 智能答疑）

**输入**：`Floyd 算法的三重循环为什么必须把 k 写在外层？`

**系统输出（节选，实录）**：

> **一句话结论**
> Floyd-Warshall 算法求任意两点间最短路径（全源），三重循环动态规划，复杂度 O(n³)、空间 O(n²)，实现极简，适合 n ≤ 500 的稠密图。[2]
> 注意循环顺序必须是 k 在最外层，且 k 表示「允许经过的中间顶点集合逐步扩大」，顺序写错会得到错误结果。[2]
>
> **知识原文摘录**
> ……注意循环顺序必须是 k 在最外层，且 k 表示「允许经过的中间顶点集合逐步扩大」，顺序写错会得到错误结果。[2]
> 出处：图论基础与最短路径 · 最短路径
>
> **再想一想**
> - 原文说「堆排序与快速排序（递归栈除外）只需 O(1) 辅助空间，属原地排序」[2]，这个结论的边界条件是什么？
> - 这一结论在空输入、单元素、极端数据下是否仍然成立？

**与标准答案对比**：

| 评分点 | 标准答案 | 系统输出 | 判定 |
| --- | --- | --- | --- |
| 关键结论 | k 必须在外层，否则状态含义错误 | "循环顺序必须是 k 在最外层……顺序写错会得到错误结果" | ✅ 一致 |
| 原因解释 | k 表示允许经过的中间顶点集合逐步扩大 | "k 表示「允许经过的中间顶点集合逐步扩大」" | ✅ 逐字命中 |
| 复杂度 | O(n³) / O(n²) | "复杂度 O(n³)、空间 O(n²)" | ✅ 一致 |
| 适用条件 | 允许负权边、不能有负权环 | 同章节同段落一并给出 | ✅ 一致 |
| 出处 | 教材对应章节 | 图论基础与最短路径 · 最短路径（可点开原文） | ✅ 可核查 |

**结论**：三个预期关键词全部命中（召回 100%），引用可定位，回答未出现"捏造教材结论"的情况。

### 案例二：主观题批改（助教 · 作业批改）

**题目**：用快速排序对数组排序，并说明最好、最坏时间复杂度和空间复杂度。

**学生作答**：`每次取第一个元素做基准，递归左右两部分。时间复杂度 O(n log n)，空间复杂度 O(1)。`

**系统输出**：

> **机器建议分：7.1 / 10**（教师可在右侧直接修正）
>
> 评分依据：
> - 关键点覆盖度 19.2%（与题目/参考答案的关键术语重合比例）
> - 篇幅充分度 80.0%
> - 结构规范性：缺少分点，建议按要点组织
>
> **逐项判定**
> - 提交算法实现时，必须显式标注时间与空间复杂度，并说明依据：时间 O(n log n)，注明 n 的含义，并说明是最好/平均/最坏。[4]
> - 把最好情况当平均情况：快速排序最好 O(n log n)、平均 O(n log n)、最坏 O(n²)，三者都要能说清。[2]
> - 空间复杂度漏算递归栈：递归实现的遍历空间复杂度是 O(h)，不是 O(1)。[2]
>
> **改进建议**
> - 重点关注：空间复杂度漏算递归栈……

**人工教研判断（对照）**：学生答案**结论方向对但有三处缺陷**——① 未区分最好/平均/最坏，直接给 O(n log n)；② 空间复杂度写成 O(1)，漏算递归栈（应为 O(log n)~O(n)）；③ 未说明基准选择对退化的影响。系统给出的 7.1 分与人工评分 7 分**误差 0.1 分**，且三条扣分依据与人工判断**一一对应**。

**价值**：教师从"逐份写评语"变为"复核并修正分数"，一份主观题批改从约 3 分钟降到约 20 秒。

## 四、对比实验：垂类检索 vs 通用检索

为说明"垂类"带来的实际差异，构造了三组易混问题，对比"仅用通用语义检索（纯向量）"与"本平台的学科消歧检索"：

| 提问 | 纯向量检索首条命中 | 本平台首条命中 | 差异说明 |
| --- | --- | --- | --- |
| 快速排序的**最坏时间复杂度** | 空间复杂度章节（因同含"快速排序""复杂度"） | 时间复杂度章节 + 排序总表 | 命中成对概念消歧规则（时间↔空间） |
| **二叉排序树**退化成链表怎么办 | 哈希表章节（同属"查找结构"） | 二叉排序树（BST）章节 + 平衡树 | 命中实体一致性规则（BST≠哈希表） |
| 建堆为什么是 **O(n)** | 堆排序流程章节 | 树与二叉树·堆与优先队列 | 命中最长短语命中 + 意图匹配（"为什么"→因果句） |

实现机制（`backend/kb_service.py`、`backend/text_utils.py`、`backend/llm_client.py`）：

1. 检索前剥离疑问词（"什么/哪些/如何/为什么"等），只保留学科术语；
2. BM25（精确术语）+ 向量（语义近似）+ 查询词覆盖率 + 连续短语命中 + 标题命中 + 权威度加权；
3. **成对概念消歧**：问"时间复杂度"时不把"空间复杂度"段落排前（12 组易混概念表）；
4. **实体一致性**：问"快速排序"时，只讲"希尔排序"的段落下沉（30+ 学科实体表）；
5. **答题意图匹配**：问"为什么"优先取因果句，问"如何"优先取步骤句。

## 七、局限性与改进方向

1. **降级路径的表达偏"摘录式"**：本报告的 2.1 节是本机 Qwen3-VL-8B 的实测（12 题准确率 100%、引用覆盖 100%）；
   2.2 节是**主动关闭大模型**后的离线检索编排（无 GPU / 无模型时才会走到），结论准确但行文不如模型自然——两条路径在界面上都有明确标识。
2. **关键词召回未达 100%（离线 88.9% / 本机 8B 模型 93.8%）**：部分参考答案使用描述性表述（如"退化"），与教材术语不同；已在做同义词扩展。
3. **55 人数据为程序生成**：规模化口径已验证，但真实用户认可度仍需按 5.1 模板补采。
4. **知识库规模有限**（11 篇 / 81 块）：作为课程级知识库足够，扩展到学科级需补充教材全文与论文库（已支持增量上传与一键重建）。
5. **单机部署**：当前为单实例 Flask，未做多副本与缓存；百人以上并发需前置 Nginx + 多 worker（部署说明已给出配置）。
6. **生成耗时受限于单卡**：8B 模型在 RTX 4060 8GB 上纯文本 ≈38 秒/题、读图 ≈27 秒/张（看图问答 ≈43 秒）；课程空间的导读/出题/学情建议为同步调用，讨论区助教回帖走后台线程 + 轮询。
