# 排序算法

## 排序的分类与稳定性

按数据所在位置分为**内部排序**（全部数据在内存中）与**外部排序**（数据量大于内存，需要多路归并）。按策略分为插入类、交换类、选择类、归并类和基数类。

**排序稳定性**：若待排序序列中存在两个相等的关键字 a 与 b（a 原本在 b 之前），排序后 a 仍在 b 之前，则称该排序算法稳定。稳定性在多关键字排序中很关键：先按次要关键字排序，再按主要关键字稳定排序，即可得到等价于「主要关键字优先」的结果。

必须记住的稳定性结论：

- **稳定**：冒泡排序（未交换即提前结束）、插入排序、归并排序、基数排序、计数排序；
- **不稳定**：选择排序（一次交换可能跨越相等元素）、快速排序（分区交换）、希尔排序（分组插入）、堆排序（堆顶与末尾交换）。

## 插入类：直接插入与希尔排序

**直接插入排序**把第 i 个元素插入前面已排好序的区间。最好情况（已有序）比较 n−1 次、移动 0 次，O(n)；最坏情况（逆序）O(n²)；平均 O(n²)。是**稳定**排序，且对近乎有序的数据非常高效（这也是生产环境常把插入排序作为快排小区间优化的原因）。

**希尔排序**按增量 d 分组做插入排序，逐步缩小增量至 1。时间复杂度与增量序列有关，最好可达 O(n log n)，最坏 O(n²)，属**不稳定**排序。它打破了「每次只交换相邻元素」的限制，是第一批突破 O(n²) 的算法之一。

## 交换类：冒泡排序与快速排序

**冒泡排序**每趟把最大元素「冒」到末尾。可以优化：若某趟没有发生交换，说明已有序，提前退出，最好情况 O(n)。平均与最坏 O(n²)，**稳定**。

**快速排序**是二十世纪十大算法之一。思路：

1. 选基准 pivot（取首元素、随机取或三数取中）；
2. 分区（partition）：把小于基准的放左边、大于的放右边，返回基准最终位置；
3. 递归处理左右区间。

复杂度：平均 O(n log n)，最坏 O(n²)（每次划分极端不平衡，例如已有序且固定取首元素），空间 O(log n) 平均、O(n) 最坏，**不稳定**。

工程优化手段：

- **随机化基准或三数取中**，避免有序输入退化；
- 小区间（长度小于 16 左右）改用插入排序，减少递归开销；
- 三路划分（Dutch National Flag）处理大量重复元素；
- 尾递归优化：先递归较短的一侧，较长的一侧用循环处理，保证栈深 O(log n)。

分区写法必须注意边界：以 `i`、`j` 双指针相向扫描时，必须保证基准位置的交换与递归区间不含基准，否则会死递归。面试中建议使用「挖坑法」或 Lomuto 分区，逻辑更易验证。

## 选择类：简单选择与堆排序

**简单选择排序**每趟选出最小元素放到前面，比较次数固定为 n(n−1)/2，与初始序列无关，O(n²)；交换次数最多 n−1 次，**不稳定**。

**堆排序**先建大根堆（自底向上建堆 O(n)），再不断把堆顶与末尾交换并下沉调整，得到升序序列。时间 O(n log n)（最好、最坏、平均均如此），空间 O(1)，**不稳定**。优点是空间开销极小且最坏情况依然是 O(n log n)，适合对最坏性能有要求的场景。

## 归并排序

**归并排序**把序列一分为二，分别排序后合并（merge）。时间 O(n log n)（三种情况一致），空间 O(n)，**稳定**。

它是**外部排序**的基础：数据量超过内存时，先把文件分成若干块内部排序得到归并段，再多路归并。多路归并时用**败者树**可以把每次选最小的比较次数从 k−1 降到 log₂k。

归并排序的典型应用：求逆序对（在 merge 时统计右侧元素先被取出的次数）、链表排序（无需随机访问，天然适合）、海量数据的外部排序。

## 基数排序

**基数排序**是非比较排序，按关键字的每一位从低位到高位做**分配**与**收集**（LSD 法）。时间复杂度 O(d(n + r))，d 为位数，r 为基数；空间 O(n + r)。**稳定**，且不依赖比较，但要求关键字可以按位分解。

**计数排序**（桶的思想）适合数值范围小的整数，O(n + k)；**桶排序**把数据分到若干桶内各自排序，平均 O(n + k)，最坏 O(n²)。

比较排序的**下界是 Ω(n log n)**，其证明基于决策树：n 个元素的排列有 n! 种，决策树高度至少 log₂(n!) = Θ(n log n)。因此任何基于比较的排序都不可能优于 O(n log n)，要突破只能利用关键字的其他性质（基数、计数）。

## 复杂度与稳定性总表

| 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定性 | 特点 |
| --- | --- | --- | --- | --- | --- | --- |
| 直接插入 | O(n) | O(n²) | O(n²) | O(1) | 稳定 | 近乎有序时极快 |
| 希尔 | O(n^1.3) | 依赖增量 | O(n²) | O(1) | 不稳定 | 分组插入 |
| 冒泡 | O(n) | O(n²) | O(n²) | O(1) | 稳定 | 可提前结束 |
| 快速 | O(n log n) | O(n log n) | O(n²) | O(log n)~O(n) | 不稳定 | 实际最快，需随机化 |
| 简单选择 | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 | 比较次数固定 |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳定 | 最坏有保证 |
| 归并 | O(n log n) | O(n log n) | O(n log n) | O(n) | 稳定 | 外部排序基础 |
| 基数 | O(d(n+r)) | O(d(n+r)) | O(d(n+r)) | O(n+r) | 稳定 | 非比较 |

记忆口诀：**快排快但不稳、归并稳但要空间、堆排序稳如老狗（最坏也 n log n）但也不稳、插冒归基才稳定**。

## 常见错误

1. **认为快速排序最坏是 O(n log n)**：最坏是 O(n²)，必须有随机化或三数取中保护。
2. **认为堆排序稳定**：堆顶与末尾交换会破坏相同元素的相对次序。
3. **快排分区后递归区间包含基准位置**，造成死循环或栈溢出。
4. **归并排序 merge 时未处理剩余段**，导致结果缺失元素。
5. **在主函数里对「已经排好序的数组再排序」测性能**，误以为快排退化为 O(n²) 是 bug，其实是基准选择问题。
6. **把排序稳定性与算法正确性混为一谈**：不稳定不代表错误，只是不保持相等元素的原始次序。
7. **在小数组上用归并排序**：常数和额外空间开销反而比插入排序慢。
