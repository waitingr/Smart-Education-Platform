# 数据结构与算法导论

## 数据结构的三要素

数据结构是相互之间存在一种或多种特定关系的数据元素的集合。它包含三个层面的要素：

1. **逻辑结构**：数据元素之间的逻辑关系，分为线性结构（线性表、栈、队列、串）和非线性结构（树、图、集合）。
2. **存储结构（物理结构）**：逻辑结构在计算机中的表示，基本方式有顺序存储、链式存储、索引存储和散列存储。顺序存储用一段连续空间表示逻辑相邻关系，链式存储用指针表示逻辑关系。
3. **数据的运算**：在某种逻辑结构上定义的操作集合，包括插入、删除、查找、遍历、排序等。

三者的关系是：逻辑结构独立于存储结构，同一种逻辑结构可以有多种存储实现；运算的实现效率取决于所选择的存储结构。例如线性表既可以用顺序表实现（随机访问 O(1)、插入删除 O(n)），也可以用链表实现（插入删除 O(1)、随机访问 O(n)）。

## 抽象数据类型（ADT）

抽象数据类型是指一个数学模型以及定义在该模型上的一组操作。ADT 强调「做什么」而不关注「怎么做」，其定义与实现分离。以线性表为例，ADT List 定义了 InitList、ListInsert、ListDelete、LocateElem、ListLength 等操作，而顺序表与链表只是两种不同的实现方式。

采用 ADT 的意义在于：接口稳定、实现可替换，这正是现代软件工程中「面向接口编程」思想在数据结构课程中的体现。

## 算法的五个特性

算法是对特定问题求解步骤的描述，必须具备以下五个特性：

- **有穷性**：算法必须在执行有限步之后终止，且每一步都在有穷时间内完成。
- **确定性**：每条指令必须有确切含义，相同输入只能得到相同输出，不能有二义性。
- **可行性**：算法中的操作都可以通过已经实现的基本运算执行有限次完成。
- **输入**：有零个或多个输入。
- **输出**：有一个或多个输出。

注意：程序可以不满足有穷性（例如操作系统是死循环等待事件），而算法必须有穷。

## 算法设计的评价标准

评价一个算法通常考虑四个方面：

1. **正确性**：对合法输入能给出满足规格说明的结果，对非法输入能作出正确处理。
2. **可读性**：结构清晰、注释恰当，便于人阅读与维护。
3. **健壮性**：输入非法数据时能作出反应或进行处理，而不会产生不可预料的输出。
4. **效率与低存储需求**：即时间复杂度和空间复杂度，通常以渐进分析衡量。

在工程实践中，「正确性」优先于「效率」，只有在正确的前提下讨论优化才有意义。过早优化是常见工程反模式：应先保证算法正确、可读，再针对实测瓶颈进行优化。

## 学科方法论

学习数据结构与算法，核心是建立三种能力：

- **抽象能力**：从具体问题中抽取数据元素及其关系，选择合适的逻辑结构；
- **建模能力**：把逻辑结构映射到存储结构，设计高效的运算实现；
- **分析能力**：用渐进分析工具评估方案的时间与空间代价，在多种方案间做出权衡。

真实工程中，选错数据结构往往比写错代码代价更高。例如需要频繁按 key 查询时应优先考虑哈希表（平均 O(1)），需要维护有序序列并频繁取最值时应考虑堆或平衡树（O(log n)），而不是在无序数组上做线性扫描。
