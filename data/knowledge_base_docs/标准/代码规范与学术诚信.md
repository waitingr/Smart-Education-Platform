# 代码规范与学术诚信规范

## 代码规范：命名与格式

课程实验与工程代码应遵循统一规范，推荐以 PEP 8（Python）或 Google C++ Style Guide 为基线，核心要求如下：

- **命名**：变量与函数用 `snake_case`（Python）或 `camelCase`（Java）；类名用 `PascalCase`；常量全大写 `MAX_SIZE`；布尔变量以 `is_` / `has_` 开头。禁止 `a`、`b`、`tmp1`、`data2` 这类无语义命名。
- **函数长度**：单个函数建议不超过 50 行，圈复杂度不超过 10，超过时应拆分。
- **注释**：注释解释「为什么」，而不是复述「做了什么」。公共函数必须有文档字符串，说明参数、返回值与异常。
- **魔法数字**：禁止在代码中直接写 100、3.14 之类常量，应提取为具名常量。
- **异常处理**：禁止空的 `except: pass`；捕获异常后必须记录日志或向上抛出，不得静默吞掉。
- **资源管理**：文件、数据库连接必须使用 `with` 或 try/finally 确保释放。

## 复杂度标注要求

提交算法实现时，必须显式标注时间与空间复杂度，并说明依据：

- 时间：`O(n log n)`，注明 n 的含义（例如 n 为数组长度），并说明是最好/平均/最坏。
- 空间：只计辅助空间，递归实现需注明递归栈深度。
- 若使用了特殊数据结构（哈希表、堆、并查集），需说明其操作的单次与总体代价。

示例格式：

```
时间复杂度：O(n log n)，n 为 nums 长度；由排序主导。
空间复杂度：O(1)，仅使用常数个额外变量（不含返回数组）。
```

## 学术引用规范（GB/T 7714—2015）

参考文献应按 GB/T 7714—2015 著录，常用类型与格式：

- **专著**：主要责任者. 题名[M]. 版本项. 出版地：出版者，出版年：引文页码.
  例：严蔚敏，吴伟民. 数据结构（C 语言版）[M]. 北京：清华大学出版社，2007：45-52.
- **期刊论文**：主要责任者. 题名[J]. 刊名，年，卷（期）：起止页码.
- **会议论文**：主要责任者. 题名[C]//论文集名. 出版地：出版者，出版年：页码.
- **学位论文**：主要责任者. 题名[D]. 保存地：保存单位，年份.
- **标准**：标准编号 标准名称[S]. 出版地：出版者，出版年.
- **电子资源**：主要责任者. 题名[EB/OL]. （发布日期）[引用日期]. 网址.

正文中引用处需标注序号，如「快速排序的平均复杂度为 O(n log n)^[1]^」，序号与文末参考文献一一对应。

## 学术诚信红线

以下行为属于学术不端，任何情况下都不得为之：

1. **伪造数据**：编造、篡改实验数据或调查结果，包括「为了让曲线更好看」而修改数值。
2. **虚构文献**：引用不存在的论文、捏造作者、伪造 DOI 或期刊名。大模型容易「幻觉」出看似可信但实际不存在的文献，因此**所有文献必须逐条核验**。
3. **抄袭与洗稿**：直接复制他人成果不加引用，或仅替换同义词。
4. **代写代做**：由他人（或 AI）完成应独立完成的实验与论文。
5. **一稿多投、重复发表**。

## AI 生成内容的使用规范

在教学与科研中使用大模型，应遵守以下边界：

- **可以使用**：辅助理解概念、生成练习题、润色语言、检查格式、生成代码框架。
- **必须声明**：凡由 AI 生成或大幅修改的内容，应在提交物中明确标注（例如脚注「本段由 AI 辅助生成并经作者核验」）。
- **必须核验**：AI 给出的定义、公式、复杂度结论与文献必须与权威教材/原文比对，不得直接采信。
- **不得使用**：用 AI 编造实验数据、伪造参考文献、代写整篇论文的主体论证部分。

平台侧对应措施：系统对所有 AI 输出附加「AI 生成内容」标识，并在学术写作场景内置学术诚信检查，对「帮我编造文献」「伪造实验数据」等请求直接拒绝并记录审计日志。
