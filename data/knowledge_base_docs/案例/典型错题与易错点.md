# 典型错题与高频易错点

## 案例一：链表反转丢失后继

**题目**：就地反转单链表。

**错误代码**：

```python
def reverse(head):
    prev = None
    while head:
        head.next = prev   # 错误：先改了 next，链表后半段丢失
        prev = head
        head = head.next
    return prev
```

**错误原因**：修改 `head.next` 之前没有保存 `head.next` 的原值，修改后 `head.next` 已指向 prev，`head = head.next` 实际回退到 prev，循环无法推进。

**正确写法**：

```python
def reverse(head):
    prev = None
    while head:
        nxt = head.next     # 先保存后继
        head.next = prev
        prev = head
        head = nxt
    return prev
```

**知识点**：链表指针操作的通用原则是「先保存、后修改」，任何一次指针重定向之前都要确认不会丢失后续结点的入口。

## 案例二：递归缺少终止条件导致栈溢出

**题目**：求二叉树高度。

**错误代码**：

```python
def height(root):
    return 1 + max(height(root.left), height(root.right))
```

**错误原因**：缺失 `if root is None: return 0` 的基线条件，空结点仍会访问 `.left`，抛出 AttributeError；若有环则死递归。

**正确写法**：

```python
def height(root):
    if root is None:
        return 0
    return 1 + max(height(root.left), height(root.right))
```

**延伸**：递归深度等于树高，单支树退化为 n，Python 默认递归上限约 1000，深树应改用显式栈遍历。

## 案例三：二分查找死循环

**错误代码**：

```python
def search(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:          # 错误：闭区间应为 <=
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left if nums[left] == target else -1
```

**错误原因**：区间定义为闭区间 `[left, right]`，但循环条件写成 `left < right`，当目标在最后一个位置时循环提前退出；同时 `nums` 为空时会越界访问 `nums[0]`。

**修正**：闭区间用 `while left <= right` 并配合 `right = mid - 1`；或统一改成左闭右开 `[left, right)`、`while left < right`、`right = mid`。两种风格不可混用。空数组需提前返回 `-1`。

## 案例四：快速排序对有序数据退化

**现象**：对已经升序的 10 万条数据调用固定「取首元素为基准」的快排，耗时从 0.02 秒暴涨到数十秒，甚至栈溢出。

**原因**：有序数组上每次划分都极端不平衡（一侧 0 个、另一侧 n−1 个），递归深度达到 n，复杂度退化为 O(n²)，栈空间 O(n)。

**修复**：

1. 随机选择基准或三数取中（首、中、尾的中位数）；
2. 小区间（长度 < 16）改用插入排序；
3. 先递归较短一侧、较长一侧循环处理，把栈深压到 O(log n)。

这说明「平均复杂度 O(n log n)」不等于「任何输入都快」，必须考虑最坏情况与输入分布。

## 案例五：负权图使用 Dijkstra

**现象**：某同学在带负权边的图上运行 Dijkstra，得到的距离大于正确答案。

**原因**：Dijkstra 的贪心正确性建立在「边权非负」之上——已确定集合中距离最小的点，其最短距离不会被后续路径更新。存在负权边时，后续可能通过负边构造更短路径，已「确定」的结论失效。

**修复**：改用 Bellman-Ford（O(n·e)，可检测负权环）或 SPFA；若需求是全源最短路且 n 较小，用 Floyd-Warshall（可处理负权，不能有负权环）。

## 案例六：哈希表删除元素后查找失败

**现象**：用线性探测实现哈希表，删除一个元素后，原本能查到的另一个元素查不到了。

**原因**：删除时把槽位置为空（None），后续元素的探测链在此处被截断，查找时提前判定「不存在」。

**修复**：使用墓碑标记（DELETED），查找时遇到墓碑继续探测、插入时可复用墓碑位置；或改用链地址法从根本上规避该问题。

## 案例七：混淆「时间复杂度」与「实际耗时」

**现象**：学生用 O(n) 的哈希查找替换 O(log n) 的二分查找后，程序反而变慢。

**原因**：哈希函数计算、内存随机访问的缓存未命中、以及数据规模较小时哈希表初始化开销，使常数因子远大于对数级差异。渐进分析只描述增长趋势，小规模或缓存敏感场景必须实测。

**结论**：选型时先看量级，再看常数；性能优化必须以 profile 数据为依据，不能只凭复杂度表。

## 复习建议

1. 每类数据结构准备 3 个「边界用例」：空输入、单元素、极端值。
2. 写完递归先写终止条件，再写递推式。
3. 涉及下标的代码，先在纸上标出区间开闭，再落笔。
4. 提交前用「手工追踪」跑一遍最小样例。
